## Correction

The superseded record says, for `guard nonce wait 0` at uptime 156.50, that
"the nonce was already there". That is wrong. In `pmos-self-post.sh` the
`trace "guard nonce wait $i"` line sits inside the `while [ ! -f
"$GUARD/nonce" ]` loop body, so it is printed only when the nonce is ABSENT at
the check. Measured reading:

- 156.50 (kmsg 156504738): the nonce was absent when self-post first asked,
  0.5 s after the transition line. This is the same early ask that killed
  run 95 (156.548).
- One `sleep 1` later the loop test saw the nonce: `post check guard armed and
  unacknowledged` at 157.51 (kmsg 157510393). The nonce therefore appeared
  inside that one-second window (156.50 to 157.51). The `append-entry` state
  snapshot at 157.52 shows `guard/nonce present [regular file 0:600:1:65]`.
- Measured: the mint happened within about 1.0 s of the wait start. The exact
  mint instant is not observable (the loop polls at 1 s). Inferred: that it
  is the same ~1-2.5 s after cutover seen in runs 93/94; this boot confirms
  an upper bound of about 1.5 s after the transition line (156.0), tightening
  the host inference of #268 with a measurement on the failing shape.
- Hence the wait is what made the check pass: the pre-#270 script (run 95)
  would have died here. Hypothesis (a) of #268 (timing) is now confirmed on
  the phone, not only inferred from acked runs.
