## Reproducible postmarketOS userspace for a held stock-kernel USB session (#139, host-only, 2026-10-27)

**Host preparation, not a phone result.** `scripts/build-alpine-session.py` assembles a RAM-only aarch64 userspace from public Alpine v3.21 main/community and postmarketOS v24.12 packages. It includes the real `postmarketos-base` package and its complete resolver-selected dependency closure, not just BusyBox plus WLAN clients. The frozen `scripts/alpine-session-packages.lock` records **134 APKs**, each package/version, source repository, APK/installed size and SHA-256. The builder pins three signed APKINDEX archives (SHA-256: main `c3bde290…`, community `9864a888…`, postmarketOS `acd75f7d…`), verifies signatures using the packaged public repository keys, checks every APK against the index and the lock, and installs the frozen set with `apk.static 2.14.6 --initdb --no-scripts --no-commit-hooks --no-network --allow-untrusted` into an external temporary directory. The `--allow-untrusted` flag is only for the local file-list transaction; the signed-index provenance and byte-exact APK SHA checks occur **before** this step. Alpine APKs additionally pass `apk verify` against the Alpine key; postmarketOS APKs use rotating buildfarm signing keys, so their signed index + per-APK hash pin is the relevant trust chain. Package scripts are never executed.

Inputs: `apk-tools-static-2.14.6-r3` x86_64 APK SHA-256 `f0e0d34d6a8f1f9d8704bae6612b4627b96f13cd20db759e9b43085135cd234f` from Alpine v3.21/main/x86_64, plus the **134** lockfile entries. The intended world was `postmarketos-base=38-r3 iw=6.9-r0 wpa_supplicant=2.10-r11 dropbear=2024.86-r0 iproute2-minimal=6.11.0-r0`; `apk add --simulate` selected exactly the lock set. The installed closure includes musl 1.2.5-r12, BusyBox `sh` 1.37.0-r14, apk-tools 2.14.6-r3, Dropbear 2024.86-r0, OpenSSH 9.9_p2-r0, `iw` 6.9-r0, wpa_supplicant 2.10-r11, iproute2 6.11.0-r0, OpenRC 0.55.1-r2 and eudev 3.2.14-r5. OpenRC, eudev, boot-deploy, mkinitfs, cryptsetup and unl0kr are **packaged but not started or used to change the boot chain, device state or partitions**. Original diagnostic PID 1, gadget, stock 6.1.84 kernel, stock modules/firmware and USB SSH remain independent.

Host run: `python3 -B scripts/build-alpine-session.py --offline` from the cached public inputs (default external cache/output under `~/sm7635-build/i139-userspace/`) and `scripts/test-alpine-session.sh`. Two serial offline builds were byte-identical: output `postmarketos-session-aarch64.tar.gz`, **23,713,302 bytes**, SHA-256 **`7a76a11062615387af5eac8f67b7f672d5f9004decac89529396d442ab3c6e26`**, extracted regular-file payload 73,767,447 bytes, indexed installed-size sum 73,588,180 bytes (~70 MiB), APK byte total 23,969,312 bytes. Check 390 aarch64 ELF files (including the mode-111 `bbsuid` setuid helper), musl interpreter and zero missing NEEDED libraries. `/etc/os-release` comes from `postmarketos-base` and reads `ID="postmarketos"`, `VERSION_ID="v24.12"`; `/etc/alpine-release` reads `3.21.9`. The staged `/etc/shadow` locks root's password (`!`); no host key or `authorized_keys` is packaged. The tarball and cache stay **outside Git**, are not boot images, and contain no firmware, partition content, WLAN profile or credential.

Negative host fixtures in `scripts/test-alpine-session.sh` reject duplicate/missing packages, invalid hash/repository/size, cache/output overlap, in-repo output, corrupted APK and index, wrong-architecture ELF and missing NEEDED library. A real `apk` offline-file install refuses a missing `musl` provider (exit 99), so the dependency closure fails closed. Host QEMU+bwrap runs `/bin/sh`, `apk`, `iw`, `wpa_supplicant` and Dropbear from the produced tarball. A separate host-only loopback chroot on port 34511 with **synthetic temporary test keys** proved key-only SSH entering that postmarketOS shell (UID 0), independent `uname -r` and `/etc/os-release`/`/etc/alpine-release`, and runnable apk/iw/wpa_supplicant/ip; password auth was disabled. This proves host execution and key-only service mechanics, **not** the phone's running userland, WLAN or memory capacity. The test service and host mounts were stopped/unmounted afterward.
