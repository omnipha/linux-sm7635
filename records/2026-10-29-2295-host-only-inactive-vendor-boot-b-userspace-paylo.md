## Host-only inactive `vendor_boot_b` userspace payload and self-staged session (#164, 2026-10-29)

**Host-only — no flash, partition write, physical boot or phone result. #164 stays OPEN until a coordinator-observed physical session.** The preferred carrier is the inactive slot-B `vendor_boot_b` partition. An unused extent of `super` is the fallback and is not used here. `scripts/build-vendor-boot-b-userspace-payload.sh` wraps `scripts/build-vendor-boot-b-userspace-payload.py`. Stock `vendor_boot_a` and `vendor_boot_b` must each be 100,663,296 bytes with SHA-256 `23725940…` and be byte-identical. The builder keeps the stock signed prefix through offset 18,256,512 (AVB0 at 18,255,872) and the terminal 64-byte `AVBf` footer, zeroes the rest, and writes one 4,096-byte ASCII header at offset 18,870,272 (SHA-256 `2d09f260…`) plus the pinned 23,713,302-byte archive at offset 18,874,368 (SHA-256 `7a76a110…`). Output stays outside Git. Two serial builds under `flock` must be byte-identical, and `--self-test` and `--verify` fail closed on a changed prefix, footer, header, archive, gap or size. On 2026-10-29 `--verify` of the built image reproduced SHA-256 `1bdb7c22…`. That value is valid only while the builder and these inputs are unchanged; rebuild and re-verify before relying on it.

`scripts/build-init-boot-self-stage.sh` wraps `scripts/build-init-boot-self-stage.py` and `scripts/verify-init-boot-self-stage.py`. It starts from the measured `fef03008…` handoff image and stock `init_boot_a`, changes only `/init` by one detached self-stage hook, and adds one root-only xz bundle of the pinned public scripts plus the private profile as a mode-0600 build input. The profile content, its source path and its digest are not recorded here. Two serial builds must match. The image SHA changes while the bundled scripts are still being edited, so this record does not pin it.

`scripts/pmos-self-stage.sh` runs on the guest. It waits at most 145 s for a regular `/run/keep` and checks the diagnostic `:22` listener, so the 150 s self-recovery timer is not outrun; the PID-1 handoff still enforces its 151.01 s settle after the hold. It finds exactly one live `PARTNAME=vendor_boot_b` in sysfs and reads that block node only, checking the node numbers, the 100,663,296-byte size and the header digest before copying the archive window and checking its size and SHA-256. It then runs the pinned session stage, replaces the ephemeral `:2222` key with the diagnostic host key and logs that public key, so the host can pre-pin `[172.16.42.2]:2222` and use strict-key checking before the host ack. No host push of root or a profile is needed. `scripts/pmos-self-post.sh` starts from the guest `local` hook only after OpenRC `default`/`local`, the switched root and the 160 s host-owned guard (`scripts/pmos-pid1-ack.sh`) ack for this boot. Before each of `modem`, `wpss`, `driver`, `scan` and `services` it waits for a fresh host-verified capture marker released at root-only `/run/self-stage-capture-marker`: mode 0600, one line, not reused, and present in this boot's kmsg. The coordinator controls each boot; nothing here powers the phone on unattended.

`sh scripts/test-pmos-self-stage.sh` is the host fixture and the reproducibility check. It runs the builder self-test, attaches the built image read-only through a loop device, and rejects a missing, duplicate or wrong `PARTNAME`, node numbers, size, header or archive digest before staging, all without a partition write. It also plants a by-name `vendor_boot_b` link to the `super` device to confirm the script reads the sysfs `PARTNAME` node instead.
