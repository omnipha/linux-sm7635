## Host-only OpenRC `networking` + `wpa_supplicant` staging on the unchanged session image (#160, 2026-10-29)

**Host-only — no device operation, flash, partition write, new image SHA or phone claim.** Run 56 (#150) associated and reached the network with a hand-started supplicant and DHCP. `scripts/pmos-radio-bringup.sh` gains a `services` stage that replaces those two hand-started processes with the distro OpenRC services on the same post-cutover stack, using only guest RAM. The unchanged `fef03008…` image is reused; nothing here builds or writes a boot image.

`prepare` now also verifies the diagnostic `/run/wlan-udhcpc-lease.sh` against the pinned `86ebff20…` digest and copies it into guest `/run/radio-bringup/`. `services BOOT_ID services CAPTURE_MARKER` then requires, in order: a fresh capture marker, `wlan0`/phy registered with both remoteprocs running, no radio fatal in this boot's kmsg, a healthy guest `:2222` (pidfile, Dropbear command line, root, TCP listener), the profile on standard input (never argv, and refused on a TTY), the pinned lease helper, the pinned `networking` (`334b6856…`) and `wpa_supplicant` (`a648c230…`) init scripts, the pinned `conf.d/wpa_supplicant` (`1600be06…`, no `-f`), no `/bin/ip`, only `default/local` enabled in any runlevel, `local` started and the two services stopped, root-owned config directories and none of the files it is about to write. A missing or non-root-only profile ends with `profile missing or not root-only` and removes the partial file.

It then writes, mode 0600, `/etc/wpa_supplicant/wpa_supplicant.conf` (from stdin only), `/etc/network/interfaces` (`auto wlan0`, `inet dhcp`, `dhcp-script` and `udhcpc-opts -t 5 -T 3 -A 5 -n`) and `/etc/conf.d/networking` (`ifquery=` pointing at a one-line `wlan0`-only wrapper), enables only `wpa_supplicant` and `networking`, and runs `rc-service -D wpa_supplicant start`, a 2 s status check and `rc-service -D networking start`. `-D` matters: without it OpenRC pulls `udev` through `dev-settle`. A `services.attempted` marker is written before the first start, so a failed first start is not retried in the same boot; the first failing service is reported and the other is not started by hand.

Four run-56 and archive facts are encoded rather than remembered: this `wpa_supplicant` v2.10 has no `-f` (the conf.d pin refuses any argument change); the lease helper must use `/sbin/ip`, so `dhcp-script` points at a RAM wrapper that sets `IP_CMD=/sbin/ip` and `exec`s the unchanged pinned helper (an `export` in `conf.d/networking` does not reach `udhcpc`); ifupdown-ng's `dhcp` executor only looks for `/sbin/udhcpc` and `ifup` calls `/bin/run-parts`, so both are symlinked to BusyBox; and `ifquery --list -a` always adds an implicit `lo`, hence the `wlan0`-only wrapper. `udhcpc-opts` puts `-n` last because the executor runs `eval echo $IF_UDHCPC_OPTS` and a leading `-n` is swallowed by `echo`. `-n` makes a missing lease exit 1, so `networking` fails closed instead of backgrounding.

`sh scripts/test-pmos-radio-bringup.sh` adds mocked refusals (missing prerequisites, pre-enabled `sshd`/`udev`/`tmpfs`, a `-f` argument, `/bin/ip`, no `:2222`, a radio fatal, a missing profile, a failed supplicant start that must not start `networking`) and one positive run checking order, modes, the wrapper and exactly three runlevel links, then a refused repeat. `sh scripts/test-pmos-session-dev.sh` additionally runs the actual archive `wpa_supplicant` and `networking` init scripts in the staged root over strict-key `:2222` with a dummy `wlan0`, a synthetic profile and a synthetic `udhcpc`: both reach `started`, `sshd`/`udev`/`tmpfs` stay stopped, the lease helper applies a synthetic address, default route and resolver through `/sbin/ip`, and both services stop. That fixture does not run a real supplicant association or DHCP exchange, and its dummy `wlan0` has no `phy80211`, so the init script's wireless-interface discovery logs `Could not find a wireless interface` and the supplicant starts without `-i`; only the real post-cutover `wlan0` can exercise that path.

This proves host ordering and fail-closed behavior only. Whether the services stay started after the real modem/WPSS path, associate, obtain a lease and reach the gateway, DNS and the internet is **unmeasured** and stays one coordinator-held session. The WLAN profile is never read, printed or committed by this change.
